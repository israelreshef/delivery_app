# 📄 מדיניות שימור נתונים (Data Retention Policy)

מדיניות זו מגדירה את משך הזמן שבו שומרת המערכת נתוני דוחות מס שנוצרו עבור שליחים, בהתאם לדרישות רשות המסים (7 שנים).

## 1. טווח

- דוחות מס אוטומטיים שנוצרו במסלול `POST /api/courier/forms/<form_id>/generate` ונשמרו בטבלת `courier_report_history`.
- כל דוח שומר: מטא-דאטה (טופס, תקופה, תאריך יצירה) + עותק PDF (`file_bytes`) + `content_hash` (sha256) + `source_fingerprint` לזיהוי התיישנות.

## 2. תקופת שימור

| סוג רשומה | תקופת שימור | בסיס נורמטיבי |
| :--- | :--- | :--- |
| דוחות מס (PDF + מטא-דאטה) | **7 שנים** מתאריך היצירה | פקודת מס הכנסה, דיני שומה |
| רשומות Audit של יצירה/הורדה/מחיקה | 7 שנים | חוק המחשבים / הנחיות אבטחת מידע |

## 3. מחיקה אוטומטית (Retention Job)

מחיקה אוטומטית של רשומות מעל 7 שנים **אינה מופעלת** כברירת מחדל.
בעת הפעלתה נדרש:

1. אישור עסקי (הנהלה/משפטי) — השימור עשוי להידרש מעבר ל-7 שנים בנסיבות שונות (סכסוך, ביקורת).
2. החלטה אם למחוק גם את עותק ה-PDF (WORM) או לשמור מטא-דאטה בלבד.
3. יישום כ-job תקופתי (Celery) שיסמן/ימחק רשומות עם `created_at < now - 7 years`.
4. תיעוד אירועי מחיקה ב-`log_audit` עם action `retention_deletion`.

## 4. WORM (Write Once, Read Many)

- עותק ה-PDF נכתב פעם אחת ב-`generate` ומעודכן ב-upsert בלבד (אותה תקופה). אין שינוי בדיעבד של רשומות קודמות.
- `content_hash` משמש לאימות שלמות הקובץ בהורדה.

## 5. אחריות

- Backend: טבלת `courier_report_history` + endpoints history/download/delete.
- הגנת בעלות: כל קריאה מסוננת לפי `courier_id` של המשתמש המחובר (BOLA/IDOR נבדקו ב-tests).
