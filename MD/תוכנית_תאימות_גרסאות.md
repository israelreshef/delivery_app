## 4. כללי שדרוג והנחיות
- **אחד בכל פעם:** לבצע ולבדוק כל שדרוג בנפרד (לעיתים יחיד ב-pr).
- **KSP חייב להתאים ל-Kotlin** — בכל שדרוג Kotlin שדרוג KSP יחדיו (פורמט `2.1.20-<ksp>`).
- **Backend:** אחרי כל שינוי — `cd backend && pytest` (כולל test_privacy/websocket/payments).
- **Frontend:** `cmd /c npm run lint` + `cmd /c npm run build`.
- **Mobile:** `.\gradlew.bat :courierApp:assembleDebug` + `:courierApp:test`.
- שומרים על תאימות לשני המודולים (courier + customer) — שניהם חולקים את אותו `libs.versions.toml`.
